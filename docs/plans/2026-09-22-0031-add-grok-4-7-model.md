## Open Questions & Recommendations
1. **Which Grok 4.7 variants to register?** The live API exposes only `grok-4.7` (no `-reasoning` / `-non-reasoning` split). **Recommendation: register the single ID `grok-4.7`**, mirroring how `grok-4.6` and `grok-4.5` are handled.
2. **Reasoning levels.** `models.dev` reports `low/medium/high/xhigh` — identical to `grok-4.6`. **Recommendation: mirror `grok-4.6` exactly**, including legacy `defaultVariant: 'high'`. No `none` variant, unlike `grok-4.3`.
3. **Context/output limits.** `models.dev` reports 500k/500k for both context and output. The existing code is internally inconsistent: the provider rule caps `maxOutputTokens: 128000` while the legacy spec says `output: 500000` (this is already true for `grok-4.6`). **Recommendation: mirror `grok-4.6` verbatim** rather than "correct" it, and treat reconciling that inconsistency as a separate change — fixing it here would silently alter Grok 4.6 behavior in the same PR.
4. **What about the other newly visible IDs?** `grok-4.20-multi-agent-0309` also appears in the live list, and `grok-imagine-*` are image/video generation. **Recommendation: out of scope for this request.** Register only `grok-4.7`; the `grok-imagine-*` models cannot be served by a `/v1/chat/completions` proxy at all, and adding the multi-agent ID is a separate product decision.
5. **Version number.** **Recommendation: `0.3.3`**, an additive model-registry patch consistent with the `0.3.1`/`0.3.2` precedent of a patch bump per incremental fix.
6. **Grok pricing in `server/cache/pricing.js`.** Grok has no pricing records today, so Grok cost display is already `not_found`. Grok 4.7 matches Grok 4.6's price table exactly. **Recommendation: leave pricing out of scope** for this change and track it as a separate follow-up covering all Grok models at once.

## Risks
- **Low.** The change is purely additive to a static registry plus a version bump. The `providerForModel` prefix check (`grok-*` → `xai`) already covers the new ID, so no routing, auth, or streaming code changes.
- The one genuine unknown is whether the subscription serves `grok-4.7` through chat completions; verification step 4 resolves that directly. If that call fails while `/v1/models` lists the ID, stop and report rather than shipping the registration.
